`env` values are sent with the deploy and applied when the agent starts that
release. They are not baked into the image.

```yaml
env:
  vars:
    PORT: 3000
    API_URL: $BASE_API_URL
  inherit:
    - DATABASE_URL
```

| Field | Meaning |
| --- | --- |
| `vars` <span className="doc-optional">optional</span> | Map of names to literals or `$NAME` values |
| `inherit` <span className="doc-optional">optional</span> | Names copied from the current environment as-is |

You can set project-level `env` and also per-app `env` under
[Apps](/docs/cli/configuration/apps). On deploy they are merged; project and
registry-injected keys win on conflict.

## Environment expansion

Fields that support `$NAME` read that value from the process environment:

| Field | Meaning |
| --- | --- |
| `elevon.agent.url` | Agent URL |
| `elevon.agent.key` | Agent API key |
| `registry.username` | Registry username |
| `registry.password` | Registry password or token |
| `routing.port` | Container listen port |
| `routing.tls.cert` | Certificate PEM content |
| `routing.tls.key` | Private key PEM content |

`env.vars` values may also use `$NAME`. `env.inherit` copies named variables
from the current environment as-is.

`registry.server` is a plain string and is not expanded.
